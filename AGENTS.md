# AGENTS.md

Fine-tune **Qwen2.5-VL-7B-Instruct** bằng **QLoRA** cho chữ viết tay tiếng Việt (mặc định `MODEL_NAME` = 7B; đổi sang 3B bằng `--model`/env khi cần nhẹ hơn). Mục tiêu thiết kế: **chỉ thêm kiến thức, không mất kiến thức gốc** → base model đóng băng, chỉ train LoRA adapter (lr 1e-5–2e-5, 1–2 epoch). Đừng nâng lr (~2e-4) hay kéo dài epoch. KL-regularization (mặc định bật) chống catastrophic forgetting; chỉ tắt (`--no-kl`) khi VRAM hẹp.

## Chạy & verify

- Entry points: `python scripts/train.py` (train), `python scripts/eval_ocr.py --image <path>` (OCR ảnh/PDF/DOCX) hoặc `--num-test N` (CER/WER, mặc định 100; thêm `--no-adapter` để chạy zero-shot base, `--few-shot K`/`--retrieval-index` để few-shot, `--prompt`/`--max-new-tokens`/`--spell-fix`/`--load-4bit` để tinh chỉnh), `python scripts/export_merged.py` (merge LoRA→full model, cần GPU), `bash scripts/pack_zeroshot_ollama.sh [3b|7b] [token]` (đóng gói base zero-shot → GGUF+mmproj → Ollama, không train/không merge), `python scripts/build_retrieval_index.py` (index CLIP cho few-shot retrieval), `python scripts/build_local_dataset.py` (gộp ảnh crop + `labels.csv` → DatasetDict local, không cần HF), `python scripts/ui.py` (Gradio), `scripts/export_gguf.sh` (Linux/Colab, sau export_merged). `main.py` chỉ là stub config.
- Scripts tự `sys.path.insert(0, project_root)` — chạy trực tiếp, đừng import như module.
- `run_train.sh` / `run_train.bat`: auto-cài uv + deps + torch-CUDA rồi gọi `train.py`. Token HF làm arg đầu (tự ghi `.env.dev`), mọi flag còn lại truyền thẳng qua. Ưu tiên `.venv` nếu có. Cả 2 set `UV_LINK_MODE=copy` và cache HF trong project (`.hf_cache`, tôn trọng `HF_HOME` có sẵn). **Mặc định (không cờ)**: chỉ cài `gradio`+`dotenv`+`pymupdf`+`python-docx` rồi mở UI ngay — `--ui` mode còn cài thêm `bitsandbytes`+`transformers`+`peft` best-effort để nút Fine-tune trong UI không OOM (thiếu → fallback full-precision → OOM 14.56 GB). **Cờ riêng**: `--train` (install full + train thật), `--eval[=N]` (eval sau train, mặc định 100). UI offline: `GRADIO_SHARE=0`.
- Batch quirk (đã verify): `=` là delimiter của cmd → `--eval=50` thành 2 arg (wrapper nuốt số sau `--eval`); đừng parse `--eval*` bằng regex findstr (`*`/`$` hỏng sau `[...]`); không ngoặc đơn trong echo/REM nằm trong block `if (...)`.
- `.sh` quirk: giữ `HAS_ARGS` thay vì `[ ${#NEW_ARGS[@]} ... ]` (mảng rỗng + `set -u` crash bash cũ).
- `requirements.txt` **không** chứa torch (PyPI mặc định bản CPU; wrapper cài CUDA `cu128`). Ghim `torchao>=0.16` trừ Windows (`sys_platform != "win32"`): peft `ImportError` khi gắn adapter nếu dính torchao 0.10.0 của Colab; chế độ UI cài best-effort.
- Smoke test: `python scripts/train.py --max-samples 100`. Lint: `pylint configs src scripts main.py` (phải exit 0 — CI `.github/workflows/pylint.yml` chạy đúng lệnh này trên Python 3.13; config trong `pyproject.toml`, max-line 120). Local: cài extension Pylint của VS Code (tự đọc `pyproject.toml`, báo ngay khi gõ) + `pre-commit install` 1 lần để hook chặn commit lỗi (entry `scripts/lint_hook.py` tự tìm python có pylint trong `.venv`, không thấy tool thì bỏ qua chứ không chặn; hook đặt `PYTHONUTF8=1` khi gọi pylint — console Windows cp1252 không in được tiếng Việt nên pylint crash). Không test suite — verify nhanh bằng `python -m compileall configs src scripts main.py` (PowerShell không expand `src/**/*.py`).

## Cấu trúc & config

- `configs/configs.py` là nguồn sự thật duy nhất; `README.md` đã cũ (bảo default 3B + "5 tab" UI) — tin `configs.py` (7B) và `scripts/ui.py` (6 tab). `scripts/train_qlora.py` chỉ là shim deprecated gọi `scripts/train.py`. `ADAPTER_DIR` tự suy từ `MODEL_NAME` + precision (`adapter_dir()`: QLoRA → `models/qwen25vl-7b-vi-hwr-lora/`, bf16 → `...-lora-bf16/`). CLI: `--dataset/--model/--epochs/--lr/--batch-size/--max-seq-len/--lora-r/--lora-alpha/--no-kl/--no-4bit/--push/--hub-repo/--resume/--save-steps`. `train.py` tính lại `ADAPTER_DIR` sau khi biết `--model` + `--no-4bit` (class attribute tính 1 lần — không làm vậy sẽ ghi đè nhầm adapter). `--no-4bit` = LoRA full-precision bf16 thay vì QLoRA 4-bit. Ảnh đưa thẳng vào processor (không pad/crop) — processor tự resize trong budget `MIN_PIXELS`/`MAX_PIXELS`.
- `src/datasets/`: `detect_columns()` auto-dò cột (đừng hard-code tên cột); ảnh giữ nguyên, chỉ `convert("RGB")` rồi để processor resize theo `MIN_PIXELS`/`MAX_PIXELS` (không pad A4 — dataset `5CD-AI` là ảnh crop **dòng**, pad A4 chỉ đổ token vào nền trắng).
- `src/datasets/collator.py`: mask `labels=-100` cho prompt + padding, **chỉ giữ loss ở assistant content + `<|im_end|>`**. Ranh giới lấy từ `attention_mask` (độ dài thực) trừ số token của answer — **KHÔNG** tokenize prompt tách rời để tính `prompt_len`: Qwen2.5-VL nở `<|image_pad|>` thành nhiều vision-token nên cách cũ để lọt ~15 token ảnh vào loss (đã đo). Giữ `add_special_tokens=False` (batch/answer/prompt, `predict.py`) — bỏ ra lệch 1 token. `min_pixels`/`max_pixels` chỉ truyền khi khác None (transformers mới validate chặt).
- `src/modeling/load.py`: chọn precision qua strategy `PrecisionLoader` (`QloraLoader` 4-bit NF4 / `Bf16Loader` full-precision, factory `resolve_loader` fallback khi thiếu bitsandbytes) — thêm mode mới chỉ cần tạo loader. `load_model_and_processor` trả `(model, processor, use_4bit)` thực sau fallback — trainer dùng nó (không phải `config.USE_4BIT`) để chọn optimizer. Giữ `remove_unused_columns=False`, `gradient_checkpointing_kwargs={"use_reentrant": False}`. Attention qua `resolve_attn_implementation` (flash_attention_2 nếu có, không thì sdpa) — đừng đọc config trực tiếp.
- `src/train/kl_trainer.py`: `loss = CE + KL_COEFFICIENT * KL(ref || active)`, ref = forward với `disable_adapter()` (no-grad), không cần copy model.
- `src/train/trainer.py`: lưu adapter + `training_metadata.json` vào `ADAPTER_DIR`; push cần `--hub-repo owner/repo`.
- `src/infer/predict.py`: `adapter_dir` là path local **hoặc** repo id `owner/repo`; base phải cùng họ adapter. Có `ocr_pdf()` (render theo `PDF_DPI`) và `ocr_docx()` (đúng thứ tự đọc, cả ảnh trong bảng). Trang scan lớn (cạnh > 1200px) tự chẻ `PAGE_TILES` lát ngang chồng nhau (`split_strips` — chẻ TRƯỚC khi processor thu nhỏ để giữ chi tiết, mỗi lát OCR riêng rồi gộp). CLI eval/export nhận `--model`.
- UI (`scripts/ui.py`): **bố cục kiểu HuggingFace Hub** — header `_hub_header` (badges base/precision/dataset) + tab (Model card · Inference · Evaluation · Fine-tune · Files & Export · Settings) + sidebar phải `_hub_sidebar` (thông số: base/dataset/precision/LoRA/train/dtype/spell-fix/adapter/GGUF + token); theme `gr.themes.Soft()`. Dropdown Base model riêng mỗi tab, đổi model tự trỏ adapter về default (`sync_adapter`); nút nặng gọi `_free_gpu()` trước subprocess; Export 2 nút (thư mục + GGUF full-chain, GGUF yield 3-tuple, chỉ Linux, skip merge nếu fresh; `export_gguf.sh` convert 2 lần text + `--mmproj` vision rồi tự sinh `Modelfile` FROM+ADAPTER+SYSTEM OCR cho Ollama; `push_gguf_ui` đẩy cả model + mmproj cùng thư mục; nút import vào Ollama đang chạy (`import_ollama_ui` — check CLI + server + Modelfile, chạy `ollama create` với cwd là thư mục gguf); nút push adapter/GGUF lên Hub (cần HF_TOKEN Write + repo `owner/repo`); 403 = sai owner hoặc token Read. Tab Settings: lưu token (hiện tên tài khoản), kiểm tra cache model (`check_model_ui`). OCR/Eval có checkbox **Zero-shot (bỏ adapter)** + ô Prompt tùy biến; Export có nút **đóng gói base zero-shot → Ollama** (`pack_zeroshot_ui` → `pack_zeroshot_ollama.sh`, `_run` nhận `env`) và nút **push model local lên Ollama registry** (`push_ollama_ui` — `ollama cp` + `ollama push`, cần `ollama login` trước).

## Zero-shot (không fine-tune)

- `eval_ocr.py --no-adapter` chạy base model thuần (không LoRA); `--prompt` ghi đè `SYSTEM_PROMPT` (áp cho cả ảnh lẻ, PDF, DOCX), `--max-new-tokens` ghi đè `MAX_NEW_TOKENS` (mặc định 256 — dễ cắt cụt trang dài). Dùng để đo baseline CER/WER trước khi quyết định fine-tune.
- `scripts/pack_zeroshot_ollama.sh [3b|7b] [HF_TOKEN]`: snapshot base → `export_gguf.sh` (GGUF + mmproj) → `ollama create` + test (± dòng `Added image`) → tùy chọn `PUSH=1 OLLAMA_REPO=<user>/<name>` để `ollama push`. Mặc định zero-shot (không adapter); đặt `ADAPTER=<dir>` thì `export_merged.py` merge LoRA vào base **trước** khi convert (cần GPU VRAM ~2x). Artifact zero-shot = base Qwen2.5-VL (Apache-2.0) + SYSTEM prompt, không thêm kiến thức.
- Few-shot/retrieval **không bake được** vào GGUF (phải ở tầng app: gửi nhiều ảnh trong 1 request). Zero-shot thì đóng gói trọn (weights + SYSTEM prompt trong Modelfile).

## Few-shot & retrieval (không fine-tune)

- `src/infer/predict.py:predict_image_fewshot` chèn K cặp (ảnh mẫu → text) rồi tới ảnh query trong **1 prompt đa ảnh** (multi-turn), dùng chung `_generate` với `predict_image`; ảnh mẫu cũng qua `_prepare_image` (RGB) cho nhất quán.
- `eval_ocr.py --few-shot K` lấy K mẫu **cố định** từ train split (`--few-shot-seed`); thêm `--retrieval-index <npz>` thì chuyển sang **retrieval theo ảnh** (K mẫu gần query nhất). Chỉ áp cho ảnh lẻ và eval (PDF/DOCX vẫn OCR từng lát kiểu zero-shot).
- `python scripts/build_retrieval_index.py --pool 5000 --seed 42` → `models/retrieval/<dataset>-train-s42-p5000.npz`. Embedder = CLIP qua `transformers` (`openai/clip-vit-base-patch32`, **không cần dep mới**); `src/infer/retrieval.py` giữ `ImageIndex` (embeddings L2 + refs dòng gốc + meta; **faiss** `IndexFlatIP` nếu cài, fallback numpy). Index cache trong `models/` (git-ignored).
- UI Eval có Few-shot K + ô Retrieval index + nút **Xây index retrieval** (`build_index_ui`).

## Hậu xử lý tiếng Việt (chữa dấu / lỗi OCR)

- `src/infer/spellfix.py:VNSpellCorrector` chạy **pipeline 2 tầng** (Underthesea + BARTpho): (1) chuẩn hóa NFC/old-diacritics/Đ-Ð bằng **`underthesea.text_normalize`** (dep trong `requirements.txt`; thiếu thì bỏ qua); (2) sửa dấu/lỗi ký tự/lỗi OCR (`o↔0, l↔1, m↔rn`) bằng model HF **`nrl-ai/vn-spell-correction-small`** (BARTpho-syllable 115M) trên `transformers`, **không tự viết edit-distance**. Xử lý **theo từng dòng** (giữ cấu trúc dòng), tự cắt dòng dài theo từ (model giới hạn 256 token).
- `eval_ocr.py --spell-fix` bật; `--spell-fix-model <id>` đổi model (mặc định `config.SPELLFIX_MODEL`). In CER/WER **trước và sau** hậu xử lý để đo tác dụng.
- Thay thế: `nrl-ai/vn-diacritic-vit5-base` (chỉ dấu, Apache-2.0), `yammdd/vietnamese-error-correction` (teencode/spelling). Chuẩn hóa encoding/old-diacritics có thể dùng `underthesea.text_normalize` (tùy chọn, không bắt buộc).

## Gắn nhãn & gộp dataset (`scripts/labeling/`)

- Package SOLID, stdlib-only (không Flask), tách tầng `domain` → `interfaces` → `csv_store` → `local_source`/`hf_source` → `registry`/`service` → `gradio_app` (web layer). `cli.py` là composition root, `__main__.py` chèn `sys.path`. Thêm nguồn mới = hiện thực `LabelSource` rồi đăng ký (không sửa service/web). Web layer dùng **Gradio** (không còn HTTP server/template tự viết); `gradio_app` import lazy trong `_run_serve` nên `merge` không cần gradio.
- `scripts/run_label_editor.bat` / `.sh` (hoặc `python -m scripts.labeling serve --port 9000`) — **editor Gradio** ở `http://127.0.0.1:9000` (`gradio_app.build_app`, web layer thay cho HTTP server tự viết; `--share` để public). Nguồn `local` = `assets/` + `assets/labels.csv` (tự tạo 1 dòng rỗng/ảnh, tự backup `.bak`); nguồn `huggingface` load lazy `5CD-AI/Viet-Handwriting-OCR-v2`, sửa text lưu vào `assets/hf_overrides.csv` (không đụng dataset gốc). `--no-hf` để chỉ gắn nhãn ảnh cá nhân.
- `python -m scripts.labeling merge` gộp HF (đã áp override) + ảnh cá nhân → `data/combined/` (`DatasetDict`); local xếp TRƯỚC để subset nhỏ vẫn gồm data cá nhân; lỗi schema (thiếu cột, không phải Image, split lạ, cột ghép lệch) báo rõ. `merge --dry-run` chỉ kiểm tra. `run_train.sh --merge` tự gộp rồi train `--dataset data/combined` (ngầm bật `--train`); `run_train.bat --merge` tương tự. `pipeline_smoke_10.sh`/`pipeline_train_20k.sh` mặc định `MERGE=1` và tự cộng số mẫu local vào `--max-samples` (smoke = 10 repo + toàn bộ assets); tắt bằng `MERGE=0`. `USE_4BIT=0` (hoặc 2 wrapper `pipeline_smoke_10_lora.sh`/`pipeline_train_20k_lora.sh`) chạy LoRA bf16; artifact tách theo suffix `-lora`/`-lora-bf16`.
- `src/datasets/dataset.py:load_dataset_with_fallback` nhận cả thư mục `save_to_disk` (local) lẫn tên dataset HF. UI tách `can_edit_text`/`can_edit_split`/`can_delete`: local sửa đủ, HF chỉ sửa text (split là khóa `DatasetDict`, giữ nguyên).

## Quirk môi trường

- Python 3.13 / Windows: train thật chạy **WSL2/GPU cloud**. 3B full-precision (bf16, không QLoRA vì `bitsandbytes` chưa có trên Windows) chiếm ~14 GB — GPU tiểu dùng 14.56 GB (như T4 16GB consumer) **sẽ OOM** nếu để KL regularization bật. `train.py` tự set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` (chống fragmentation, không tăng capacity). Chạy smoke test nhanh trên Windows được: `python scripts/train.py --max-samples 100 --no-kl --batch-size 1 --max-seq-len 512`. 7B cần ~16GB+; export merged cần gấp ~2x.
- Inference dtype = `INFER_DTYPE` (`configs.py`, mặc định `"fp16"`; `"bf16"`/`"auto"` khi muốn): `resolve_infer_dtype()` dùng cho `load_ocr_model`/`export_merged`. **3B fp16 ~7.5GB → chạy được trên GPU 15GB (T4)**; 7B full-precision (~15.2GB) **không** vừa T4 → dùng `eval_ocr.py --load-4bit` (NF4 qua `bitsandbytes`, `load_ocr_model(..., load_4bit=True)`) hoặc GGUF qua Ollama.
- `run_train.sh` auto-cài `flash-attn` (best-effort, Linux only) rồi tăng `--batch-size` dần cho A100/H100.
- `HF_TOKEN` đọc env trước, fallback `.env.dev` mỗi lần khởi tạo `Configs()` (tránh stale khi lưu token giữa session). Dataset gốc gated — accept điều khoản trên HF.
