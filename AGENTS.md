# AGENTS.md

Fine-tune **Qwen2.5-VL** cho chữ viết tay tiếng Việt. Mục tiêu thiết kế: **chỉ thêm kiến thức, không mất kiến thức gốc** → base model đóng băng, chỉ train LoRA adapter (lr 1e-5–2e-5, 1–2 epoch). Đừng nâng lr (~2e-4) hay kéo dài epoch. KL-regularization (mặc định bật) chống catastrophic forgetting; chỉ tắt (`--no-kl`) khi VRAM hẹp. Hai flow train: **3B QLoRA** (default `configs.py`, dev/smoke) và **7B bf16 staged sequential** (production — xem § Staged training 7B, `.sh` cứng `--no-4bit`).

## Cấu trúc & config

- `configs/configs.py` là nguồn sự thất duy nhất. `ADAPTER_DIR` tự suy từ `MODEL_NAME` + precision (`adapter_dir()`: QLoRA → `models/qwen25vl-3b-vi-hwr-lora/`, bf16 → `...-lora-bf16/`). CLI: `--dataset/--model/--max-samples/--start-samples/--epochs/--lr/--batch-size/--max-seq-len/--max-pixels/--min-pixels/--lora-r/--lora-alpha/--no-kl/--no-4bit/--push/--push-every-save/--hub-repo/--hub-revision/--init-adapter/--adapter-revision/--run-name/--resume/--save-steps`. `train.py` tính lại `ADAPTER_DIR` sau khi biết `--model` + `--no-4bit` (class attribute tính 1 lần — không làm vậy sẽ ghi đè nhầm adapter). `--no-4bit` = LoRA full-precision bf16 thay vì QLoRA 4-bit.
- `src/datasets/`: `detect_columns()` auto-dò cột (đừng hard-code tên cột); ảnh giữ NGUYÊN gốc (dataset là ảnh crop dòng — không pad/crop, processor tự resize theo `MIN_PIXELS`/`MAX_PIXELS`). ĐÃ BỎ tính năng chuẩn hóa A4 (`standardize_a4`/`A4_STANDARDIZE`).
- `src/storage/run_store.py`: registry JSON `models/runs.json` lưu lịch sử các lần train/eval (config, adapter, hub repo/revision, CER/WER). Tra cứu bằng `python scripts/runs.py`. Nguồn chân lý để tiếp tục train vẫn là adapter trên HF Hub.
- `src/datasets/collator.py`: mask `labels=-100` cho prompt **và** padding; giữ `add_special_tokens=False` ở cả 3 chỗ (batch, prompt, `predict.py`) — bỏ ra lệch 1 token. Đo `prompt_len` trong KHÔNG GIAN MULTIMODAL (`_mask_prompt`: encode prompt bằng processor kèm ảnh) + mask dự phòng mọi image-token (`_IMAGE_TOKENS`) — đo bằng tokenizer text-only sẽ ngắn hơn hàng trăm token vì `<|image_pad|>` nở ra khi qua processor, mask sót token ảnh vào labels khiến loss ≈ 0 (đã gặp: loss 0.0 suốt 800 step). `max_length` = budget TEXT, collator tự cộng thêm budget image-token (`max_pixels/784`) vào processor (`_effective_max_length`) — nếu không truncation sẽ cắt image-token gây crash "Mismatch in image token count" (VLM khác text: chuỗi = text + image token). Log 1 lần nội dung labels batch đầu (`_log_first_batch`) — nhìn dòng này ở step 0 là biết mask đúng/sai, khỏi chạy hàng chục nghìn mẫu mới phát hiện.
- `src/modeling/load.py`: chọn precision qua strategy `PrecisionLoader` (`QloraLoader` 4-bit NF4 / `Bf16Loader` full-precision, factory `resolve_loader` fallback khi thiếu bitsandbytes) — thêm mode mới chỉ cần tạo loader. `load_model_and_processor` trả `(model, processor, use_4bit)` thực sau fallback — trainer dùng nó (không phải `config.USE_4BIT`) để chọn optimizer. Giữ `remove_unused_columns=False`, `gradient_checkpointing_kwargs={"use_reentrant": False}`. Attention qua `resolve_attn_implementation` (flash_attention_2 nếu có, không thì sdpa) — đừng đọc config trực tiếp.
- `src/train/kl_trainer.py`: `loss = CE + KL_COEFFICIENT * KL(ref || active)`, ref = forward với `disable_adapter()` (no-grad), không cần copy model.
- `src/train/trainer.py`: lưu adapter + `training_metadata.json` vào `ADAPTER_DIR`; push cần `--hub-repo owner/repo`, `--hub-revision` để push vào nhánh riêng (vd `stage-10k`); `--run-name` tách thư mục checkpoint (`models/checkpoints/<run_name>/`); cuối run ghi 1 dòng vào `runs.json`. `--push-every-save` (qua `PushOnSaveCallback`) push snapshot lên Hub mỗi `save_steps` — chống mất khi đứt giữa chừng (Modal/Colab hết phiên): máy khác `--init-adapter <repo>@<revision>` kéo snapshot cuối về train tiếp (mất ≤ `save_steps` step + reset LR; trọng số giữ nguyên). Eval loss tự bật cùng nhịp `save_steps` khi có eval set (phát hiện lệch hướng sớm: `eval_loss` phải giảm dần).

## Staged training 7B (sequential lát mới-only)

- `scripts/stage_train.sh <start> <count> <init_rev> <hub_rev> <run_name> [save_steps]` train 1 mốc, chạy nền nohup → log `train-<run_name>.log` (đã git-ignore). `scripts/stage_train_loop.sh <start> <end> <init_rev> [step] [save_steps]` chạy foreground nhiều mốc → bắt buộc tmux. **`<count>` là SỐ MẪU, không phải end-offset** (`end = start + max_samples`, `dataset.py:129`) — vd lát 5k→15k: `start=5000 count=10000`.
- `init_rev=none` = train trắng (`train.py:_split_adapter_ref` hiểu `none`); ngược lại `--init-adapter <repo>@<rev>` nạp trọng số adapter cũ (LR/step reset, khác `--resume` là khôi phục cả optimizer). Thứ tự tiếp tục: checkpoint local (`--resume`, `.sh` tự thêm khi thấy `models/checkpoints/<run>/checkpoint-*`) > `stage_progress.json` trên nhánh init (`--auto-progress`, train phần còn lại) > full lát. Cảnh báo `[auto-progress] ... không đọc được tiến độ` ở mốc đầu (nhánh init chưa có file) là benign — train đủ lát.
- Ghi đè qua env: `HUB_REPO` (repo đích, default repo 7B cũ), `INIT_REPO` (repo nguồn weight, default = `HUB_REPO` — nối repo cũ sang repo mới thì set riêng), `BATCH_SIZE`/`GRAD_ACCUM`/`LR` (chuẩn GPU 80GB: `8`/`4`, eff 32, ~156 step/5k), `LORA_R`/`LORA_ALPHA` (chỉ tác dụng khi `none`; nối tiếp thì lấy theo adapter cũ), `SUFFIX` (loop.sh tự giữ `-v2` nếu nối chuỗi `-v2`). `.sh` đã cứng dataset/model private + `--no-4bit` — đừng truyền lại.
- Trước mốc tiếp theo: `ps aux | grep train.py | grep -v grep` + `tail -n 5 train-<run>.log` xác nhận đã push `stage-Nk`. Không bao giờ chạy 2 train chung 1 GPU (OOM). `tail -f` treo terminal/Colab cell — dùng `tail -n 5`.
- Dấu hiệu train khỏe: step tăng đều, loss 0.5–2 giảm dần, checkpoint + push snapshot mỗi `save_steps`, batch đầu có dòng `[collator]` decode labels tiếng Việt sạch. VRAM phẳng (~50GB) là bình thường (caching allocator cấp 1 lần) — muốn biết GPU có bận thì xem `utilization.gpu`, không xem memory.
- `src/infer/predict.py`: `adapter_dir` là path local **hoặc** repo id `owner/repo`; base phải cùng họ adapter. Có `ocr_pdf()` (render theo `PDF_DPI`) và `ocr_docx()` (đúng thứ tự đọc, cả ảnh trong bảng). Trang A4 lớn (cạnh > 1200px) tự chẻ `PAGE_TILES` lát ngang chồng nhau (`split_strips` — chẻ TRƯỚC khi thu nhỏ để giữ chi tiết, mỗi lát OCR riêng rồi gộp). CLI eval/export nhận `--model`.
- UI (`scripts/ui.py`): dropdown Base model riêng mỗi tab, đổi model tự trỏ adapter về default (`sync_adapter`); nút nặng gọi `_free_gpu()` trước subprocess; Export 2 nút (thư mục + GGUF full-chain, GGUF yield 3-tuple, chỉ Linux, skip merge nếu fresh; `export_gguf.sh` convert 2 lần text + `--mmproj` vision rồi tự sinh `Modelfile` FROM+ADAPTER+SYSTEM OCR cho Ollama; `push_gguf_ui` đẩy cả model + mmproj cùng thư mục; nút import vào Ollama đang chạy (`import_ollama_ui` — check CLI + server + Modelfile, chạy `ollama create` với cwd là thư mục gguf); nút push adapter/GGUF lên Hub (cần HF_TOKEN Write + repo `owner/repo`); 403 = sai owner hoặc token Read. Tab Settings: lưu token (hiện tên tài khoản), kiểm tra cache model (`check_model_ui`).

## Quirk môi trường

- Python 3.13 / Windows: train thật chạy **WSL2/GPU cloud**. 3B full-precision (bf16, không QLoRA vì `bitsandbytes` chưa có trên Windows) chiếm ~14 GB — GPU tiểu dùng 14.56 GB (như T4 16GB consumer) **sẽ OOM** nếu để KL regularization bật. `train.py` tự set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` (chống fragmentation, không tăng capacity). Chạy smoke test nhanh trên Windows được: `python scripts/train.py --max-samples 100 --no-kl --batch-size 1 --max-seq-len 512`. 7B cần ~16GB+; export merged cần gấp ~2x.
- `.venv` tạo bằng `uv venv` KHÔNG có pip → luôn `uv pip install --python .venv/bin/python <pkg>`; đừng `uv add` (biến package optional thành dependency bắt buộc, vỡ install Windows).
- flash-attn: không có wheel cho Python 3.13 + torch cu128 → phải build source 10–20p. Build isolation che mất torch (`Failed to build flash-attn`, `No module named 'torch'`) → cài bằng `--no-build-isolation` (torch đã có trong `.venv`); giới hạn RAM build bằng `MAX_JOBS=4`. `.sh` tự thử best-effort mỗi lần chạy, thiếu → `[WARN] Bo qua flash-attn` rồi train tiếp bằng sdpa (chậm hơn ~15–20%, kết quả học y hệt). Cài tay lúc train đang chạy vẫn an toàn (process đã load lib; đừng upgrade torch/transformers).
- Colab: mỗi cell shell cần `!` riêng; xem log bằng `tail -n 5`, không `tail -f` (treo cell). `Ctrl+C` chỉ kill `tail`, train nohup vẫn sống — check lại bằng `ps aux | grep train.py`.
- `run_train.sh` auto-cài `flash-attn` (best-effort, Linux only) rồi tăng `--batch-size` dần cho A100/H100.
- `HF_TOKEN` đọc env trước, fallback `.env.dev` mỗi lần khởi tạo `Configs()` (tránh stale khi lưu token giữa session). Token phải của **owner repo** (quyền Write) + đọc được dataset/model private; verify bằng `python scripts/check_hf_token.py` (không nhận arg). `.env.dev` rỗng/trống gây 404 dataset — export token thật trước khi ghi file. Dataset mặc định là mirror private `tranhuy67896262/Viet-Handwriting-OCR-v2-local` — token cần quyền đọc repo này.
- `docs/staged-training-plan.md` đã stale (đề xuất cumulative + lr 1e-4/R=64/KL-off): thực tế chạy sequential lát mới-only, R=32/alpha=64, lr 2e-5. Khi doc mâu thuẫn script, tin script.
